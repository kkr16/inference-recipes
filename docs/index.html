Qwen3.8-27B — tp1-vllm-fp8-mtp4

rtx-pro-6000 · DP=8 x TP=1 · vLLM 0.34.0 · FP8 · c=1 E2E p90: 4.91 s · Peak: 2,550.3 tok/s (DP=8 @ c=8/GPU)

View on GitHub ↗
serve.sh
#!/usr/bin/env bash
set -euo pipefail

# Recipe: tp1-vllm-fp8-mtp4 (DP=8 x TP=1)
# Container: vllm/vllm-openai:v0.34.0
# Prerequisite: install the skinny Triton in_proj_ba plugin (qwen_g4_kernels) in the vLLM environment:
#   pip install git+https://github.com/jawadaminGOOG/g4-recipes.git#subdirectory=plugins/qwen_g4_kernels

export HF_XET_HIGH_PERFORMANCE=1

# NOTE: Prefix caching is ENABLED by default for production.
# Pass --no-enable-prefix-caching only to reproduce uncached stress benchmarks.
exec vllm serve Qwen/Qwen3.8-27B-FP8 \
  --host=0.0.0.0 \
  --port=8000 \
  --trust-remote-code \
  --language-model-only \
  --max-model-len=16384 \
  --kv-cache-dtype=fp8 \
  --mamba-ssm-cache-dtype=bfloat16 \
  --max-num-batched-tokens=4096 \
  --max-num-seqs=256 \
  '--speculative-config={"method":"mtp","num_speculative_tokens":4,"draft_lm_head_quantization":"fp8"}' \
  "$@"

Benchmarking Harness & Methodology

View bench/ on GitHub ↗

Shared scripts for generating exact-token synthetic workloads, running async OpenAI-compatible streaming benchmarks, and regenerating the root catalog table.

Scripts

  • scripts/make_dataset.py: Generates unique, realistic multi-turn enterprise prompts verified to tokenize to an exact input sequence length (default: 10,000 tokens, add_special_tokens=False).
  • scripts/bench_client.py: Async streaming client for /v1/completions supporting both closed-loop concurrency sweeps and open-loop Poisson arrival rates. Collects client-side TTFT, TPOT, ITL, E2E percentiles and scrapes Prometheus /metrics deltas (including speculative decoding acceptance length for both vLLM and SGLang).
  • scripts/build_catalog.py: Reads all models/**/metadata.yaml files and prints/updates the Markdown leaderboard in the root README.md.

Standard Methodology

  1. Exact token counts: Prompts are verified to exact ISL (add_special_tokens=False), and requests pass max_tokens=<OSL>, ignore_eos=True, temperature=0.0, stream=True.
  2. Uncached stress baseline: Unless a recipe explicitly benchmarks prefix caching, disable prefix/radix caching (--no-enable-prefix-caching on vLLM, --disable-radix-cache on SGLang) during measurement so every request pays full prefill cost. (Re-enable prefix caching in production!)
  3. Warmup: Every concurrency/RPS point executes un-timed warmup requests before collecting timed metrics.
  4. Zero-error gate: All published numbers require 0 failed requests.

Essential Multi-GPU Tuning Knobs (TP >= 2)

Because RTX PRO 6000 uses PCIe Gen5 without NVLink, default NCCL settings fall back to CPU shared-memory (SHM) staging for TP >= 4:

  1. NCCL_P2P_LEVEL=SYS: Unlocks direct PCIe P2P DMA inside NCCL across NODE and SYS links (~2x lower small-message AllReduce latency and 38–40 GB/s bus bandwidth on large prefill chunks).
  2. VLLM_ALLREDUCE_USE_FLASHINFER_PCIE_IPC=1 (vLLM): Activates FlashInfer's auto-tuned CUDA-IPC AllReduce for decode steps (<= 512 tokens) while keeping NCCL_P2P_LEVEL=SYS for prefill chunks. Pair with --gpu-memory-utilization=0.85 to leave headroom for FlashInfer's late-allocating IPC workspace.
  3. Prefer DP over TP for throughput: When a model fits on 1 GPU (e.g., quantized 27B–32B models), DP=8 × TP=1 typically delivers 3.5x–7x higher node throughput than TP=4 or TP=8. Use TP >= 2 only to hit strict single-request latency SLAs.
